As alterações do Araru seguem: pre-flight → Issue → branch → desenvolvimento → validação → commit → push → pull request → CI → merge → release/deploy → validação final → fechamento da Issue.

Use branches `<type>/<issue>-<slug>`, commits Conventional Commits em inglês e PRs com contexto, escopo, critérios de aceite, validação e impacto de release. Utilize `Refs #<issue>` enquanto release ou deploy ainda forem gates.

Consulte o [guia em inglês](../workflow/) e a [skill do runtime](https://github.com/araruoss/araruoss/blob/main/runtime/skills/araru-development-workflow/SKILL.md) para as regras operacionais completas.
